# 项目协作规则

1. 每个开发任务开始修改前，统一通知用户本轮预计修改的已有源码范围和目的，并取得一次明确许可。许可后可在已说明范围内连续修改，无需在执行过程中逐文件重复询问；只有需要扩大到未说明的重要旧源码或配置时才再次询问。
2. 新增源码可以在已授权的开发范围内执行；修改超出本轮已说明范围的已有源码前需要再次确认。
3. 不做掩盖错误的静默兜底。依赖缺失、状态非法、初始化顺序错误、网络发送器未注册等情况必须输出明确错误或抛出异常，使问题能在开发阶段被发现。
4. 只有产品需求明确要求的降级路径才允许存在；降级发生时必须记录包含对象、状态和关键参数的日志。
5. 默认只进行静态代码检查和低成本编译检查。不要为了日常改动启动 Unity Editor 做完整导入或批处理编译；用户会在每个里程碑结束后自行运行 Unity 项目验证。只有用户明确要求时才执行 Unity 编译。
6. 只负责代码实现，不自动修改 Unity 场景、GameObject、Prefab、组件挂载、Inspector 参数、Build Settings、ProjectSettings、Package 配置或其他 Unity 资源配置。需要配置时，向用户提供明确的对象、组件、字段和值，由用户手动完成。代码依赖的配置缺失时应明确报错，不自动创建或静默补齐。
